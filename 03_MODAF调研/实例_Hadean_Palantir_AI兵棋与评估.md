# 实例：Palantir × Hadean——用"本体"把 AI 兵棋、推演与实战接成一条线

> 用途：给 `modaf-study/` 两篇材料配的真实实例。只讲它怎么工作、怎么构成，不铺时间线。
> 为什么选它（2026-09-21 换）：原实例（NGC2 数据层）偏"数据传输与互操作"；本实例是**"评估/推演"类**——兵棋推演、方案生成、超实时仿真、what-if 对比，与课题组"体系效能评估"研究方向更贴；且主角是 Palantir 平台，落在英国 MoD 语境（MODAF 正是英国框架，语境同源）。
> 注：公开材料以厂商新闻稿/产品页为主，性能主张未经第三方验证；正式引用前建议复核原文链接。

## 一句话

英国国防部（MoD）的装备生态里，本土公司 **Hadean** 做"AI 兵棋推演 + 指挥控制"，**Palantir** 提供数据与本体底座（Foundry）。2025 年 9 月两家把产品接在一起：Hadean 的兵棋（populAI）、指挥控制（dominAI）、战场训练全部跑在 Foundry 之上，用 Palantir 的 **Ontology（本体）**当双方共享的"作战语言"——同一套实体、关系与语义**贯穿所有密级**，于是"训练里推演过的东西"可以直接带进"机密/实战环境"，不再重新翻译。

## 骨架：四块各干什么

| 块 | 干什么 | 靠什么 |
| --- | --- | --- |
| 本体层 | 把分散在不同系统、不同密级的作战数据统一成同一套实体、关系与语义 | Palantir Foundry + Ontology |
| 推演层 | 生成想定与"活的"环境（平民、社媒、交通、基础设施……），做兵棋推演 | Hadean Platform / populAI |
| 决策层 | 把多源数据合成单一可执行格式；态势感知 + 超实时仿真批量评估行动方案 | dominAI（C2） |
| 场景面 | 训练 → 任务规划 → 指挥控制 → 实兵行动，一条生命周期全贯通 | 英国武装部队及盟友 |

一句话概括分工：**Palantir 管"大家说的是不是同一种语言"，Hadean 管"用这种语言把仗推演一遍、算给你看"。**

## 本体层：跨密级的"同一种语言"

- **痛点**：防务数据分散在不同领域、不同密级；训练网里的数据结构和涉密网里对不上，AI 在训练环境学出来的东西，到实战环境要"翻译"——翻译就有损耗、有延迟。
- **Foundry/Ontology 做什么**：把数据统一起来，并给 Hadean 的 AI 与仿真工具一套**共享的操作语义**（官方表述："ontology gives Hadean's AI and simulation tools that shared operational language"）。
- **三条设计主张**（来自 Hadean×Palantir 合作页，原话意思）：
  1. **同一套本体贯穿所有密级**——兵棋推演与实战行动使用**相同的数据结构**，这是"AI 可信"的前提；
  2. **构建一次，随处部署**（build once, deploy everywhere）——能力一次开发、任意环境部署，减少重复开发、加快安全认证；
  3. **共享作战语言**——AI 只有在"按操作员理解任务的方式"理解任务时才有效。
- **为什么这条对英国特别关键**：Palantir 已深度嵌入 MoD 网络，Hadean 借这条既有管道把 AI 与仿真推入涉密环境，"远快于传统国防采购路径"。
- **对照 MODAF**：这就是 03 材料里说的"殊途同归"——MODAF 的 **M3/MODEM** 和 Foundry 的 **Ontology** 干的是同一件事（定义"有哪些实体、怎么关联"）。区别仍在老位置：M3 是**描述体系**用的数据字典（产出视图/文档），Ontology 是**运行系统**里的数据结构（兵棋、仿真、C2 直接读写它）。

## 推演层：populAI 把"演习"变成"活的"环境

- **不只是红蓝军对推**：环境里同时有平民、社交媒体、交通、卫星、动物、关键基础设施——每个要素都对行动做出**不可预测的反应**；官方定位是"对现实世界最真实的表征"。
- **行为特征**：涌现式、动态的模型行为随想定实时演变；"代表性人口行为"并可注入**本地情报**；纳入灰色地带要素（信息作战、关键国家基础设施 CNI）。
- **空间**：全 3D 单一环境，覆盖水下、海上、陆地、空中、太空五个域。
- **想定怎么建**：低代码注入——加上地点与数据，世界自动生成（免手工写脚本）；可注入 DIME 输入（外交、信息、军事、经济）与**白军、黑军**等兵力要素。
- **两个工程性质**（对"评估"很重要）：同一想定**可重复运行**（结果可复现）；想定生成自动化（批量铺场景的成本低）。
- 一句话：**兵棋里的"人"和"社会"不是背景板，而是评估对象的一部分**——"体系"不只是装备的集合。

## 决策层：dominAI 把"评估"做成分钟级

- **定位**：把 AI + 仿真**嵌进现有 C2 系统**（不是另起一个工具），目标是加快目标打击周期、跑赢对手节奏。
- **机制**：并行跑**数千次"超实时仿真"**（faster-than-real-time）→ 推演敌方位置与分支 → 批量**生成并分析行动方案（COA）**；新闻稿的表述是"向前仿真（forward simulate），实时确定最佳行动方案"。
- **输出**：分钟级（而非小时级）给出大量候选方案 + 对比分析 → **由人授权**执行；支持美/北约/英国标准，可与传感器、效应器及其他 C2 集成；构建通用作战图（COP）。
- **宣称的收益**（均为厂商说法）：更多备选与应急预案、规划更快所以留给演练的时间更多、COA 符合条令与经验教训、过滤数据降低认知负担。
- 一句话：**评估从"人读一堆报表"变成"系统把候选方案各推演几千遍、排队给你挑"。**

## 三个具体能力（其实也是例子）

1. **防空**：Hadean 官网原文——把 AI 与大规模仿真直接嵌入防空指挥控制，"即时浮现最优交战方案（optimal engagement plan），交给人授权"。
2. **任务预演**：官方机制三步——① 把静态计划导出到合成环境，置于动态共同作战图；② 接入**实时数据**（使场景反映当前态势）与**权威军事数据集**（准确表征蓝军能力）；③ **前向推演**，对方案反复压力测试（理解影响 → 探索应急 → 执行前评估权衡），官方称可"模拟任意数量的潜在行动方案"。
3. **海上 C2**：SCEPTRE 联盟（英国中小企业联合体）用 dominAI 做端到端海上 C2 集成演示（2026-02 报道），口号是把"感知—决策—打击"链打通。

## 一条线实际怎么走（训练 → 规划 → 实兵）

1. **兵棋/训练**：populAI 生成想定与世界，虚拟部队 + 真人（白军/黑军）推演；
2. **任务规划**：同一套本体下的部队、装备、地理数据；静态计划导出到合成环境做预演；
3. **C2/执行**：dominAI 用超实时仿真批量评估 COA，人选择并授权；
4. **跨密级**：官方设计主张是同一套数据结构贯穿"兵棋推演 → 实战行动"，训练与实战之间不"翻译"。
   （注：公开材料没有披露"实战数据回流训练/复盘"的闭环细节——别写死这一环。）

## 节奏：这条合作线的时间锚点

- 2024-11：Hadean 与 MoD 签下 2,000 万英镑（£20M）的 Enterprise Agreement Lite（数字兵棋与 C2 平台）；
- 2025-09-10：Palantir × Hadean 合作公布（伦敦），产品将部署在 Foundry 之上，预计**数月内**可供 MoD 在机密/实战环境使用；
- 2025-10 起：Hadean 继续扩生态（Vantor：战斗情报 + 任务预演等）；
- 2026-02：SCEPTRE 进入 MoD 的 DDAD 框架；dominAI 海上 C2 演示；
- 2026-07：Hadean 入选北约 DIANA 加速器（十家公司之一）。
- 背景：Palantir 称已为武装部队服务十余年，全球员工五分之一以上常驻英国。

## 如果被追问"这和 MODAF / DoDAF 什么关系"

只讲对得上的：

1. **元模型 vs 本体**：M3/MODEM 与 Ontology 干同一件事——定义"有哪些实体、怎么关联"。前者供人画视图、出文档；后者是运行中的数据结构，兵棋、仿真、C2 直接读写。
2. **"数据为中心"**：MODAF 里是原则——图是数据的投影，先有数据后有图；这里落成工程机制——同一套本体跨密级共享，"训练与实战不翻译"。同一个想法，一个落在文档上，一个落在系统里。
3. **框架 vs 平台**：MODAF 回答"怎么把体系描述清楚"；这条合作回答"怎么让推演、评估与决策共用一套语义"。MODAF 2021 年退役，但它要解决的问题（互操作、反烟囱）没有消失——现在的答案经常不是新框架，而是**直接把语义层做成软件**。
4. **一个英国实例**：MODAF 是英国国防部的框架；Hadean 是英国公司、客户是 MoD、Palantir 也把英国当重镇——讲 MODAF 配一个英国语境实例，比配美军实例更顺。（想看美军/DoDAF 语境的例子，用备选里的 NGC2。）

## 如果被追问"这和'体系效能评估'类研究什么关系"

三点对得上，且都对的是"机制"不是"话术"：

1. **无真值条件下的评估**：没有实战数据时，先造一个"冻结、可复现"的推演环境，把方案在仿真里跑出来当参照物——这正是"仿真当参照物"路线的工程版本；dominAI 的"数千次超实时仿真"就是"有限预算下多跑仿真"的工业化形态。
2. **"本体 = 实体 + 关系"**：和"体系 = 个体 + 关系（协同/克制）"的建模口径是同一件事的两面——先统一定义"有哪些东西、怎么关联"，再谈计算和评估；评估结果的可解释性，源头就在这层定义上。
3. **受控评测的形态**：COA 批量生成与对比 = "同一想定、改参数、比结果"；任务预演里"反复压测、执行前评估权衡"就是 What-if / 候选池排序的产品化表达。

另一个值得注意的点：populAI 把**平民、社交媒体、基础设施**放进模型——评估对象从"装备对装备"扩展到了"人和社会"，这正是"体系"二字的完整含义。

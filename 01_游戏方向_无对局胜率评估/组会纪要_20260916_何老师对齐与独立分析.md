## 一、组会内容完整纪要

### 1. 模拟器的定位与实现方式

- 课题需要**造模拟器**，其本质是**状态机**——相对离散、非连续的状态表示与转移。
- 状态转移的两个例子：
  - **王者荣耀**：技能打到目标身上不是必然事件，按**命中概率**判定；
  - **坦克大战**：炮弹进入坦克半径范围（如 0.1 米～1 米内）即判定命中。
- 通过状态转移的方式实现推演过程，这个过程本身就是模拟器。与我们之前（v3）讲的方案本质相同。

### 2. 模拟器真实性如何保证（何老师观点：下棋类比）

- 真实性的保证逻辑**与下棋一样**：规则既定好之后，模拟出来的结果就是真实结果。
- 承认模拟可能与实际情况有出入，但"真实的实际情况"本来也无从获得。

### 3. 发表方向与前景（何老师观点）

- 这个方向**四个人**一起做。
- 目前是**蓝海**、做的人少，所以**发文章很容易**。
- 发表目标：**IEEE 肯定可以**；具体投哪里取决于**突破点**——
  - 以学习为突破点 → 人工智能方向；
  - 以体系为突破点 → 体系方向。

### 4. 四人做会不会拥挤（何老师观点）

- "**如果连四个人都会打架，就说明这个领域已经饱和了**。"
- 领域足够宽广，各自看论文、看文献之后，方向会自然发散开来，不必担心方向重叠。

### 5. 论文中的数据写法（何老师观点）

- 跑实验可能用王展那边或刀海那边的数据，但写论文时**不写数据来源**，写成："我们有智能体 A、智能体 B、智能体 C……"
- 称实际情况就是如此：国防科大做体系研究非常多，现在那边发论文也都是这样写的。
- **比较推荐用游戏那边的数据**，理由是游戏数据趋于完整。

### 6. 腾讯竞争风险（双方存在分歧，已记录）

- **我方提问**：用王者荣耀会不会和腾讯打架、方向会不会直接被腾讯"干掉"？
- **何老师观点**：腾讯（策划）关注的是怎么把东西卖出去（比如卖卡）；我们关注的是体系、协同作战能力——建模之后甚至能发现"这边缺了什么"，两者不冲突。
- **我方异议（记录在案）**：不完全认同，且当时感觉自己的表述不够充分。理由：策划、游戏实验室、专门发论文的团队，研究方向肯定不一样；如果用王者，必须非常注意与腾讯的研究区分开，否则很可能被"斩杀"。

### 7. 技术路线定性

- 方法**不是纯数据驱动**，而是**模型与数据并行**——因为状态机本身就是相对离散的状态表示，所以需要造模拟器。
- 组内有人持续主张"**少样本**"。
  - 我方观点：少样本**不太能算创新点**——除非真的用很少样本做出很好效果（但这很难）；少样本顶多算**优势**。
- 关于状态机：
  - 何老师：状态机就是**一条条规则的集合**；
  - 我方理解：本质是**状态的转化**，很像**马尔可夫链**——一个状态加一个动作之后变成另一个状态。

### 8. 补充要点（第二轮补充，此前遗漏，重要）

- **研究对象澄清**：不研究 NPC 怎么运动、**不做强化学习**、不探讨"怎么动能胜率更高"；
- 研究对象是**阵容组合 / 能力分配**——假设总体能力值为 100（粗略），研究怎么分配：
  - 坦克大战例子：一方攻速快但防御低，一方攻速慢但防御高、机动性可能差（攻速高可能速度就快）；
  - 研究哪种阵容组合能使其获胜概率更高。
- **实现路径**：Python 有很多相关的智能体仿真库——只要把属性都定义好，仿真就能直接跑起来；NPC/坦克怎么运动，只需定义规则，不需要自研引擎。

## 二、独立分析结论

> 总体判断：**何老师的方向感是对的，但他的几个论证在论文层面站不住——好在 v3 + 审核报告已把这些坑提前修掉。真正要警惕的是"很容易发"的乐观，以及数据来源写法的合规风险。**

### 1. "下棋论"只对一半——论文口径必须用 v3 的版本

下棋类比对国际象棋成立（规则 = 游戏的全部，完美信息、无隐藏物理，所以模拟 = 现实），但对王者/坦克不成立：模拟器是对真实游戏的**抽象简化**——手写的命中概率、伤害公式、决策规则 ≠ 腾讯服务器里的真实代码，更没有真人玩家的操作分布。审稿人一定会抓这一点，且最新游戏仿真论文已在专门批评前人"只做定性观察、不用真实数据做数值验证"。

这正是审核报告标记的"循环论证"致命缺陷，v3 已修复：口径从"模拟器是客观真理"降级为"**冻结、可审计、可复现的参照物**"，现实锚定由第一层验证（统计指纹比对、公开赛事数据只验不拟合）单独负责。

**结论：何老师组会的口径比我们自己方案里的口径弱。写论文用 v3 口径，不用组会口径。**

### 2. "蓝海"的准确表述：交集是空的，四周全是邻居

外部文献核实（2026-09 检索）：

| 邻近领域 | 拥挤度 | 代表工作 |
| --- | --- | --- |
| 数据驱动阵容/胜率预测 | 热门，全部依赖海量对局数据 | WWW'19《What Makes a Good Team?》；CoG'22 HFN（实时胜率预测 84.7%）；TSSTN |
| 游戏平衡仿真 | 快速增多 | 有限仿真预算下的平衡边界发现；GEEvo；RuleSmith（LLM 自动调平衡） |
| 兵棋推演 + 智能体 | 2025–2026 明显爆发 | AAAI 2026 Symposium 多智能体兵推策略合成 |
| 装备体系贡献率评估 | 国内军口期刊已开专栏 | Shapley 值、马尔可夫过程、A-GERT 网络、杀伤网中心性 |

**准确表述：'零对局数据 + 机理状态机模拟器 + 胜率语义输出 + 可检验校准'这个交集确实是空的，但四周全是邻居。** 两层含义：

- 好的一面：划界故事（汇报大纲第九节四句话）经得起查；
- 坏的一面：这个交集之所以空，部分原因是"无数据验证"天然让审稿人警惕。**蓝海和荒漠只有一线之隔**，区分落在哪边的是验证体系做得诚不诚实——v3 里"公开数据只验不拟合"那道关不能省。

### 3. "很容易发"：出口对，难度打折

- IEEE 方向（ToG / CoG）确实是正确出口；汇报大纲的阶梯（CoG/ToG 练手 → AAMAS 主目标 → AAAI/IJCAI 应用 track 冲刺）比"很好发"更接近现实。
- 该方向审稿人池子活跃、标准在涨，"随便做就能发"不成立；"方法链完整 + 验证诚实 + 划界清楚"的工作发 CoG/ToG 级别是**现实预期**。
- 何老师的乐观适合鼓舞士气，不适合排时间表；v3 里"模拟器阶段可能超预算 2–3 倍"的估计更靠谱。

### 4. 四人拥挤：论证是循环的，结论碰巧成立

- "四个人会打架 = 领域已饱和"在逻辑上不成立（四人打架更可能只是共用同一个模拟器代码库、抢同一个实验场景）。
- 但结论同意：可切方向确实够四个人分——评估函数、模拟器保真、主动预算分配、归因分析、体系应用。
- **真正要尽早做的不是担心学术撞车，而是把四个人的切口和模拟器代码归属白纸黑字写清楚**：谁造模拟器、谁做公式、谁做替身模型、论文一作怎么算。

### 5. 腾讯风险：警觉正确，实际概率可控，但要预置一个审稿问题的答案

- 何老师答错了对象：腾讯策划确实不管发论文，但**腾讯 AI Lab 的绝悟团队就是发论文的**——王者绝悟论文进过 AAAI、NeurIPS，有真引擎、真数据、大规模 RL。我方警觉是健康的。
- 实际风险可控：他们做"用海量数据训练更强的 AI"，我们做"零数据条件下的评估方法"——**约束本身就是护城河**，他们没有动机也没有优势做这个约束下的问题。
- 真正的风险是一个具体的审稿问题："**腾讯开悟平台已经开放了环境和 baseline，你为什么不用？**"必须预置答案（开悟要训练数据和算力；我们是零数据评估范式），写进相关工作。
- 学术界用王者做实验对象是通行做法（上文引用论文均如此），合规层面风险低。

### 6. 少样本：不算创新点；手里的牌是"零对局数据"

- 少样本本身不是创新点，是约束条件；few-shot learning 本身是红海，单拿它当卖点必死。
- 关键：**我们实际做的是"零对局数据"，比"少样本"强一档、清晰一档**。零数据机理驱动评估是更稀缺、更好划界的定位。
- 组里若有人想把故事讲成 few-shot，应顶住，不自降身价。

### 7. 状态机 = 马尔可夫：直觉正确，论文按 MDP/DES 语言写

- "状态 + 动作 →（按概率）→ 新状态"就是**马尔可夫决策过程（MDP）**的标准定义；坦克"进入距离阈值判定命中"是**离散事件仿真（DES）**里标准的事件触发转移。
- 何老师"一条条规则的集合"是工程说法，马尔可夫是数学说法——**论文直接用 MDP/半马尔可夫 + DES 的语言形式化**，接入现成理论和审稿人熟悉的词汇。
- 含义：状态机本身**没有概念创新**，创新点在"怎么用这台机器做评估、归因和验证"，创新点陈述别放错位置。

### 8. 数据来源的写法：国际发表下是审稿与合规的双重风险

- "用了王展/刀海的数据但写成智能体 A、B、C"——国内军口期刊常见，但投 IEEE/国际会议时，可复现性要求越来越高，数据来源含糊可能被直接拒稿，性质上接近数据来路不实。
- **何老师推荐用游戏数据是对的解法，但理由说错了**——不是因为"数据完整"，而是因为游戏数据**公开、可复现、无从质疑**。
- 坚持汇报大纲既有策略：游戏是主实验场（数据干净），军事只作为应用场景一句话带过。这条线守不住，前面所有技术优势都白搭。

### 9. Python 库查证：属实，但"定义好属性就能动"只对一半

查证结论：这类库确实存在且生态成熟——

| 库 | 是什么 | 对本课题的用处 |
| --- | --- | --- |
| **Mesa** | Python 最主流的 ABM 框架：定义 Agent 类 + 属性 + 每步行为规则，调度器自动推进，自带数据采集与参数批量实验、浏览器可视化 | 最贴近"定义好规则就动起来"；Mesa 3.0 工程化程度高 |
| **SimPy** | 基于标准 Python 的过程式离散事件仿真（生成器建模主动实体） | 与"状态机 + 事件触发命中"设定天然匹配 |
| **Salabim** | 离散事件仿真 + 动画（组件/队列/状态/监视器） | 调试期"肉眼检查行为合理性"很有用 |
| **PettingZoo**（butterfly 系列） | 多智能体环境标准 API，含坦克对战类网格战斗环境；策略可接脚本，不强制 RL | 环境现成；将来加 RL 对比实验的最低成本入口 |

- 防跑偏：AutoGen/CrewAI 之类是**大语言体编排框架**，与物理/规则仿真是两码事，别被"智能体库"关键词带偏。
- **对的那一半**：引擎层的活不用干了——调度循环、事件队列、碰撞检测、回合推进、数据记录、批量重跑，库全包；v3 算力账（单对阵 1–3 CPU 小时）在这些库上完全成立。
- **不对的那一半**："动起来" ≠ "动得对"——往哪动、打谁、何时接团（v3 的 4–5 条决策原则）库不管，仍要自己写，而这正是审核报告认定最大风险的部分。
- **正确读法**：基础设施风险基本清零；风险没有消失，而是**全部集中到了决策规则上**——与 v3 预判一致（"模拟器阶段可能超预算 2–3 倍"，且超只超在写规则这一件事上）。

### 10. 研究定位（不做 RL、只做组合）：正确，而且是护城河，不是妥协

1. **控制变量的实验设计**：行为策略冻结、只变阵容组合，阵容的因果效应才能干净测出；真做 RL，行为和阵容混在一起，胜负归因说不清。这一点还与腾讯绝悟划清界限——他们优化"玩得好"，我们测量"组得对"。
2. **审稿人必问："你的结论是不是只在你的脚本策略下成立？"** 答案：是，条件成立，且我们量化了这个条件——v3 的"操作水平旋钮"+"假设扰动稳健性报告"就是为此准备的。处理好了，它反而变成"阵容 × 操作水平"这个数据驱动方法做不到的分析维度（数据里阵容和操作分不开）。
3. **"总能力值 100 怎么分配"框架的辨析**：它把研究问题从"评估任意阵容"变成"固定预算下的分配优化"——两层是上下楼关系：**评估函数 = 目标函数，分配方案 = 搜索空间**。固定总预算的好处：搜索空间有界；"把 10 点从防御挪到攻速、胜率变多少"这类 what-if 查询成为改进建议的天然形式。又因克制关系存在，**最优分配依赖对手池**——不存在万能最优解，这本身可长出一节分析（接 v3 循环克制诊断实验）。

### 11. 技术选型建议（结合分阶段计划）

| 阶段 | 选型 | 理由 |
| --- | --- | --- |
| L0 数值对撞（Phase 0） | 纯 NumPy 向量化 | 无空间无运动，上框架是负资产 |
| L1–L2 有空间与运动 | Mesa 起步；需精细事件时序再 SimPy；调试期用 Salabim/Mesa 可视化肉眼查行为荒谬性（对应五道关里的极端阵容检查） | 结构规范、批量实验现成 |
| RL 对比（后手） | PettingZoo | 审稿人/导师问"和 RL 方法比呢"时的最低成本入口 |

## 三、行动项（按优先级）

1. **数据边界拍板（最优先）**：让何老师对"公开赛事数据只验不拟合"正式表态——决定第一层验证有无实证锚、决定论文主张层级（v3 Phase -1 的遗留事项，至今悬置）；
2. **论文口径锁定 v3 版本**："冻结、可审计、可复现" + 两层验证 + 真实数据只验不拟合；不采用组会"下棋即真实"的简化口径；
3. **相关工作预置答案**："为什么不用腾讯开悟平台/绝悟"——开悟要训练数据与算力，本课题是零数据评估范式；
4. **四人分工与代码归属白纸黑字**：切口（评估函数 / 模拟器保真 / 主动预算分配 / 归因 / 体系应用）+ 模拟器代码归属 + 一作规则，越早定越好；
5. **技术选型按阶段执行**：L0 NumPy → L1 Mesa（+SimPy/Salabim）→ PettingZoo 备用；
6. **口径纪律**：坚持"零对局数据"定位，不降级为 few-shot；
7. **模拟器设计文档更新**：把组会新增的"命中概率 / 事件触发命中"细节并入；"结论条件于冻结策略"写进 limitation；
8. **写作纪律**：实验数据来源在论文中如实描述（游戏为主实验场），不使用"智能体 A/B/C"式的来源隐匿写法。
